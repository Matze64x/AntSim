# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

AntSim is a C++20 Vulkan ant colony simulation. Ants search for food, carry it to their nest and leave food and home trails in a hash grid that other ants follow; all of it runs in Slang compute shaders, rendered with a graphics pass and an ImGui UI.

There are no unit tests. Validation is interactive — run the application and watch the simulation.

## Build Commands

```bash
cmake -S . -B bDebug -DCMAKE_BUILD_TYPE=Debug
cmake --build bDebug -j$(nproc)
# Run (finds the ant_shaders/ directory walking up from the CWD)
./bDebug/AntSim [map.png]   # e.g. maps/barrier.png
```

The first build compiles vkTurboEngine's vendored Slang library, which takes a while. Shaders need no build step: the engine compiles the Slang shaders from source in-process, at startup and on **F5** (or the UI's **Reload Shaders**). `python ant_shaders/compile_shaders.py` is a standalone validator that runs `slangc` over every shader (writing throwaway `.spv` files to the gitignored `ant_shaders/bin/`).

In a Debug build, compiling the shaders at startup takes ~10 s (Debug Slang), and the window only appears (maps in sway) after that. Presenting uses FIFO, which on Wayland blocks while the window isn't shown (other workspace, locked screen), so the loop stalls and doesn't react to closing until it is visible; for headless tests switch `present_settings` in `run_application()` to `eMailbox` temporarily. To check behavior without screenshots, a temporary hook can read the nest buffer back (`vkte::Buffer::obtain_first_element<Nest>()` after `engine.wait_idle()`) and print the delivered food every simulated minute.

Controls: left mouse drag pans (the grabbed point stays under the cursor), the mouse wheel zooms about the cursor, the right mouse button adds food under the cursor (**Food Amount**) or paints/erases walls (the UI's **Right Mouse** tool and **Wall Brush Radius**), **G** toggles the UI, **F5** reloads the shaders.

## Architecture

- `main()` finds `ant_shaders/` and calls `run_application()` (`src/application.cpp`), which creates the `vkte::Engine` and the `WorkContext` and runs the event loop; UI requests (reload shaders) are flags in `AppState` that the loop handles between frames. `AppState::view` (`View`) is the shown part of the world: a center and a height, whose width follows the window's aspect ratio so that world units are square on screen; mouse positions map to the world with `View::to_world()` and `AppState::window_size` (window coordinates, not the swapchain's pixels).
- `WorkContext` (`src/work_context.cpp`) owns the `Simulation` component and records each frame: after `Engine::begin_frame()` it updates the frame's uniform buffer, records the simulation (preceded by filling the buffers with the simulation's start on the first frame and on **Reset Simulation**) and then, after a barrier, the drawing of the hash grid, the ants and the UI (`UI` in `src/ui.cpp`, the ImGui window) with dynamic rendering into one command buffer on the graphics queue; a separate compute queue wouldn't overlap anything, since vkte runs the frames one after another. (Every `Command::submit_*()` of a frame waits for the previous frame's.)
- `Simulation` (`src/simulation.cpp`) is the one `vkte::Component`: `declare_resources()` creates the ants', nest's and hash grid's bindless buffers and declares the pipelines; it builds the push constants and records reset (buffer fills), step and draw.
- The simulation advances by fixed steps of `SIMULATION_TIME_STEP` (`ant_shaders/modules/push_constants.slang`): each frame runs as many steps as fit in the accumulated real time (a frame counts as at most 0.1 s) times `AppState::simulation_speed` (the UI's **Speed**, 0 pauses), each step a dispatch of `step_ants` and `update_hash_grid`. `PushConstants::step` is the step a pass computes (for drawing the steps done); shaders derive the simulated time (`step * SIMULATION_TIME_STEP`) and the random seeds from it, so nothing in the simulation depends on the frame rate. Runs still aren't bitwise reproducible: ants update cells concurrently in `update_hash_grid` (deliberately, so that every ant in a crowded cell acts each step).
- Ant behavior (`ants_shaders.slang`) comes from a few physical mechanisms instead of tuned probabilities, each a named constant at the top of the file: ants walk with a heading that drifts randomly; ants searching for food lay the home trail and steer toward food or the food trail that tells the shortest way to food, smelled with three antennae (left, ahead, right), or, smelling neither, away from the home trail (toward the antenna that smells the longest way home or none), so that they explore outward and where no ant has been; ants carrying food lay the food trail and steer toward the home trail that tells the shortest way home, or, smelling none, toward `get_nest_estimate()`, where they believe the nest is from path integration (the nest plus an error that grows with the square root of `Ant::distance_walked`, in a direction and scale derived from the ant's index, so no estimate is stored per ant). Antennae smell where their trail leads (food cells for the food trail, nest cells for the home trail), and an ant that smells it heads straight for the nearest such cell instead of following the trail. Both trails are distance fields: a cell keeps the shortest way back (`Ant::distance_walked`) of any ant that passed, home for searching ants, from the food for carrying ones (an atomic maximum on the complemented float bits, so the zero fill means none), aging by `TRAIL_AGING_SPEED`; ants adopt a shorter way that their cell's trail tells, so the fields converge on the shortest explored ways, around walls too, any ant that strays onto a shorter way shortens them, and following decreasing values never chases an ant; an ant adopts a cell's way only plus the cell's diagonal (a cell tells the way from anywhere in it; without that margin, ants re-adopt what they laid a step before in the same cell, and their way grows only as fast as trails age). The nest is a point, its cell, so that all ways meet there. A share of ants (the UI's **Explorer Share**, `BehaviorSettings::explorer_share`) explores at any time: they walk randomly instead of following trails. `is_explorer()` derives it from the ant's index and time slots of a search distance's walk (shifted per ant), so the share holds however long trips are; deciding per departure overshot it on maps with short trips. `TRAIL_AGING_SPEED` must stay below `ANT_SPEED` (it is half of it, so that trails ants stopped laying, to food that is gone or past a new wall, soon lose to the ones in use; ants erasing dead ends was tried and dropped: they ate whole stale patches cell by cell instead of switching, and a slower aging of a tenth isn't needed for shortcuts to win): otherwise the fresher part of an ant's path tells a shorter way than the older part nearer its source, and followers chase the ant instead of going back. Ants ignore ways longer than `MAX_TRAIL_DISTANCE`. Ants turn back on taking food and on delivering it. `Ant::state` (`AntState`) is `Search`, `CarryFood` or `GiveUp`: a searching ant gives up with a chance per meter of 2 × way home / search distance² (so it searches farther out than a way home d with chance exp(−(d / search distance)²); the UI's **Search Distance**, `BehaviorSettings::search_distance` in the uniform buffer) and then heads home like a carrier, taking food it passes. How far searchers roam trades exploring far against finding nearby food: the maze map needs ~40 m, nearby food does best with ~20 m. Each antenna (`Smell`) reads every cell once for food, the nest and both trails' distances. An ant whose step would enter a wall steps along the free direction nearest its heading (turned by multiples of `WALL_TURN_ANGLE`) but keeps its heading up to `WALL_PRESS_ANGLE` into the wall, so it slides along walls, follows them through openings on that side and leaves them when its heading drifts away; antennae smell nothing in walls. Headings drift slowly (`HEADING_PERSISTENCE_LENGTH`, 5 m), since ants that turn often only wander around the nest.
- Walls are a dense bit grid over the whole world (`modules/walls.slang`; a bit per hash grid cell, 5000×5000 cells = 3 MB), not hash grid cells, so they have no collision gaps; cells outside the world count as walls, which bounds the world. The `paint_walls` pass (`world_shaders.slang`) paints or erases the frame's `WallStroke` (the cursor's way since the last frame, so fast strokes leave no gaps). **Reset Simulation** keeps the walls; **Clear Walls** (and the first frame) empties them.
- Maps (`include/map.hpp`, `src/map.cpp`) are PNGs (examples in `maps/`), loaded from the command line at startup, a pixel per hash grid cell, centered on the world's origin: black is wall, green food (green 1-255 is 1 to 2^`MAX_FOOD_EXPONENT` = 2^30 food per cell, on a log scale), blue the nest (at the blue pixels' center); a pixel counts as the color whose channel is more than twice the others. `load_map()` builds the walls' bits and the initial hash grid on the CPU (with `get_hash_grid_slot()`, which `modules/hash_grid.slang` shares with C++ through `AS_FUNCTION`; food pixels whose slot another took are dropped with a warning); `Simulation::set_map()` uploads them (outside frames, after `engine.wait_idle()`), and **Reset Simulation** copies `initial_hash_grid_buffer` back, so it restarts the loaded map. Images are read with stb (`dependencies/stb`, from PhotonDust).
- Every pipeline takes the same `PushConstants` (`ant_shaders/modules/push_constants.slang`): the bindless buffer handles, which shaders resolve with `vkte::get_buffer<T>()`, and the ant count and hash grid capacity.
- Rendering has no depth attachment, so draw order decides what is on top: the hash grid's full-screen pass first, then the ants.

## Shader Organization

All shaders are Slang in `ant_shaders/`. The shader files, the ones with entry points (`[shader("...")]`), end in `_shaders.slang` and sit directly in `ant_shaders/`, several entry points per file, which `vkte::Shader` selects by name: `ants_shaders.slang` (the ants' simulation step, `step_ants` and `update_hash_grid`, and drawing them) and `world_shaders.slang` (`add_food`, `paint_walls`, `age_trails` and drawing the world). Entry points must not be named like Slang built-ins (`step` fails with "no function found matching entry point name"). `python ant_shaders/compile_shaders.py` compiles every entry point it finds.

`ant_shaders/modules/` holds the modules, one per topic (`ant`, `hash_grid`, `nest`, `walls`, `push_constants`, `uniform_buffer`, `random`, `colormaps`). A module that C++ also uses holds the data shared with it (`Ant`, `HashGridCell`, `Nest`, `UniformBufferData` with its `Visualizations`, which `AppState` holds for the UI to edit, `PushConstants`, `WallStroke`, constants and enums) and, under `#ifdef __SLANG__`, the shader-side code for it, which C++ skips: methods added to the shared structs with `extension` (`Nest::get_radius()`, `Visualization::get_color()`) and shader-only types (`HashGrid`, `Walls`). C++ includes these modules as headers (`ant_shaders/` is on the include path), made valid C++ by `modules/common.slang` (which aliases `float2`/`float3`/`int2` to glm and defines `AS_CONSTANT` and `AS_FUNCTION`, for free functions both sides use); a module that needs another one imports it in Slang and includes it in C++ (in an `#ifdef __SLANG__ ... #else ... #endif` block at its top). Flags in buffers are `uint32_t` 0/1, not `bool`, whose size differs between Slang's buffers and C++.

The `HashGrid` (`modules/hash_grid.slang`) looks cells up, returning `Optional<uint>` slots; one slot per grid position, keyed by the position packed into a `uint`; a cell is alive while it has food or a trail that tells at most `MAX_TRAIL_DISTANCE`, so nothing ages or frees cells per frame; any slot whose cell isn't alive is free, and a position whose slot holds another position's living cell is wasteland, where nothing is laid. Cells have no locks: ants take food with an atomic decrement, claim a free slot with a compare-exchange on its key and lay a trail with an atomic maximum. Cells store the trails as of a trail epoch's end (`TRAIL_EPOCH_STEP_COUNT` steps; `HashGrid::trail_aging` converts), and the `age_trails` pass ages every cell once after each epoch's last step, so aging costs no pass per step.

Buffers are read through pointers (`vkte::Buffer<T>::get_pointer()`) wherever a shader writes single members, since `vkte::Buffer<T>`'s subscript reads and writes whole elements; atomics cast a member's address to `Atomic<T>*`. Shaders use scalar layout, so C++ structs only need the same members in the same order. Types are written out: no `let`/`var` in Slang (unwrap an `Optional<T>` with `hasValue`/`value`) and no `auto` in C++.

## Dependencies

- `vkTurboEngine` — Vulkan abstraction (git submodule, shared with PhotonDust); it vendors Slang (a nested submodule, `git submodule update --init --recursive`), SDL3, spdlog, ImGui and VMA
- `glm` — math
- `stb` — `stb_image`/`stb_image_write` (`dependencies/stb`, copied from PhotonDust) for maps

vkte picks the first suitable GPU, which on the dev laptop is the Intel Iris Xe, not the NVIDIA RTX 4080. The Iris Xe has no float atomic add (`shaderBufferFloat32AtomicAdd`), so shaders don't use it; enabling vkte's `shader_atomic_float` would make it unsuitable.
